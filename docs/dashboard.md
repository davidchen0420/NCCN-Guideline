# OncoCarta (interactive viewer)

OncoCarta is a React + TypeScript app (in `web/`) that turns the encoded guidelines into a reader that finds the NCCN recommendation for a patient and links each step to its NCCN page. It reads the canonical `data/<slug>/guideline.json` files directly (`web/src/lib/adapt.ts`), so every one of the 91 encoded guidelines works without a per-guideline build.

```
cd web && npm install && npm run build && cd ..                     # app -> src/nccn_nav/dashboard.html
PYTHONPATH=src python -m nccn_nav.dashboard --library               # all guidelines -> built/oncocarta.html + built/guidelines/*.js (open directly or serve)
PYTHONPATH=src python -m nccn_nav.dashboard data/<slug> [out_dir]   # one guideline, offline -> <out_dir>/<slug>-oncocarta.html
PYTHONPATH=src python -m nccn_nav.dashboard --sample out            # synthetic demo data (older format), safe to share
```


## Using OncoCarta
This section describes what a clinician sees. The sections after it are technical. Plain-language wording lives in `web/src/lib/terms.ts`; the encoding words (route, fit, arm, extraction) are used only in the technical sections and in Advanced tools. For a one-page guide with no code, see [`clinician-guide.md`](clinician-guide.md).

OncoCarta is a research prototype, not an official NCCN tool. Conditions were drafted by software and are not clinician-reviewed, so every recommendation links to the NCCN page it came from. The disclaimer (`T.prototype`) sits beside each recommendation, in the summary and on the home page.

### Home
The app opens on the map of all guidelines (details under *Atlas*, below). The search box asks **Which cancer or topic?** and finds guidelines (title, abbreviations, aliases such as CLL or GIST), cancer sites, sections and pages. Choosing a guideline opens its panel:
- **Find a recommendation for a patient** opens the reader on the Patient tab.
- **Read the guideline** opens the reader at the guideline's first start page.
- **Example patients**: pick one to see its best match drawn on the map (the card says *Best match* and *Matches your answers* or *Needs N more answers*), then **Open in the reader with this patient**. A patient entered earlier in this session appears as *Your patient*.
- **Where to start** lists the start pages, titles first with the code after. **About this guideline** holds the version, the guidelines it refers to and the disclaimer.

A **List** view (`#list`) shows the same guidelines as a plain list grouped by category; opening one reads it. On the very first visit a welcome screen offers three ways in: enter a patient, try an example, read the guideline.

### Reader
The left rail has **All guidelines** (back to the map at the page being read), **Contents**, **Search**, **Help** (also the `?` key) and **Settings**. Above the page, the title bar has Back and Forward, the page title with its code as a quiet suffix, a link to the official NCCN guidelines and, when needed, **Connect the NCCN PDF**.
- **Contents panel** with three views: **Contents** (algorithm pages, principles, staging, discussion, references), **Overview** (every page of the guideline as a tile with where it leads) and, in Advanced tools only, **History** (pages visited and the guided walk).
- **Search panel**: exact phrases in quotes, filters (NCCN categories and preference tags, kind of result), counts by kind. Steps that do not match are grayed out on the page.
- **Right-hand panel** with tabs **Patient** and **Recommendation**. A **Step** tab appears once a step is clicked and shows that step's text, footnotes, related pages, where it leads and where it is reached from, with **View on the NCCN page**. Advanced tools keeps the Step tab always visible and adds a **Walk** tab. On a phone the panel is a bottom sheet opened by **Patient & recommendation**.
- **Three-step strip** above the panel: *Patient* (n answered), *Recommendation* (n possible), *Check the NCCN page*. The current step is highlighted, each is a button, and one line says what to do next (start with the questions that decide the first steps, or load an example; then the best next question and *See n possible recommendations*; then *Hover a step to see its NCCN page; click to open it in its own window*). It can be hidden and brought back in Settings.
- **Dock** under the diagram, three tabs: **Footnotes** (this page's footnotes, stepping through "i of N" places), **Evidence** (NCCN categories of evidence) and **Preference** (categories of preference).
- **Settings** (gear at the bottom of the rail): **Advanced tools** (off by default), **Show the 3-step guide**, **Help**, and, only when the local server offers AI (below), **AI decision support**: an on/off switch, a threshold slider (50-99%, default 85%: *Follow the AI automatically when it is at least 85% confident*) and the privacy note.
- **Canvas hint** on first visit: click a step to follow it, hover to preview its NCCN page, drag to move, scroll or pinch to zoom.

### Patient tab
1. **Where is the patient now?** Chips: Not sure, then the points in care the guideline has (New diagnosis, Follow-up, Recurrence or relapse, Advanced or metastatic, Later-line therapy). Guidelines that cover several diseases ask for the disease or subtype first. Picking a point in care starts the recommendation there and narrows the questions. Hidden for screening, prevention and supportive-care guidelines.
2. **Questions that change the recommendation** They can be answered **one at a time** (the default; number keys pick a choice, long lists are searched; *Don't know — skip* and *Back*; the count says about how many questions remain) or **all together** (*Show all questions* / *One at a time*; the choice is remembered). When the answers lead to different places, each says where (*Leads to: Regional Prostate Cancer (PROS-7)*); answers that change nothing say nothing; clicking that line chooses the answer. When no open question changes anything, the app says the result is settled by what has been entered.
3. **Paste a note** (also a button at the top of the panel): paste a clinic note or report; plain rules find ages, stages, scores, lab values and yes/no findings. Each finding shows the words it came from and what it would replace; untick any and press *Apply N answers*. Nothing leaves the browser.
4. **Worked out from your entries**: values calculated with the guideline's own definitions (for example a risk group).
5. **More details**: every other question, grouped (for past-diagnosis patients: *Current situation*, *Treatment so far*, *Original diagnosis*), with a filter on long forms and *Show all details* to widen a list narrowed by the point in care. Dimmed questions do not change any recommendation that is still possible.
6. **Carried over from diagnosis**: when the patient moves from a new diagnosis to a later point in care, answers that described the state at diagnosis are held, not used, until you mark each *Still true*, change it or clear it (*All still true* confirms the lot). Findings that do not change (germline, biomarkers, histology) and treatment history carry over as they are.
7. **Top of the tab**: *n answered*, a strip of **Entered so far** (click to change, × to clear), and a **More** menu with *Save this patient*, *Saved patients*, *Load an example* and *Start over*. Saved patients are kept in this browser only (`localStorage`, `oc-saved:<slug>`, at most 30).
8. **Checks**: implausible numbers (units, ranges) and contradictions (for example M0 with metastases recorded) are flagged beside the field or at the top.

### Recommendation tab
One card for the best match, then the alternatives. Above them: *N possible recommendations for this patient*.
- **Best match** (or *Also possible* / *Less likely*) with **Matches your answers** or **Needs N more answers**. These words come from the ranking; they are not probabilities.
- **NCCN recommends**: the recommendation box itself, with its tiers and tags (Preferred, category), then *Then:* what follows and a button to open that page, and the box's footnotes.
- **On the NCCN page**: a thumbnail of the page (when the PDF is connected), the page title with its code, the PDF page number, **Verify on the NCCN page** (opens in a new window) and **Show this page in the diagram**.
- **Why**: the patient answers that satisfied the conditions on the way here (first four, *Show all*).
- **Still unknown**: questions whose answers could change the recommendation (click to jump to the field) and a note when steps on the way rely on your clinical judgment.
- **Summary to copy or print**: a one-page record (patient answers, the recommendation with its structure, what is still unknown, how the patient gets here, what comes next depends on) with *Copy as text* and *Print*, ending with the disclaimer.
- **Other possible recommendations**: up to four, then *Show all*. Recommendations that end in the same box count once. Picking one replaces the card and lights it up on the diagram.
- **How the patient gets here**: the pages on the way, as buttons.
- **How we got here** (under the card, collapsed): the decision trail, `web/src/components/Trail.tsx`. The summary line counts the decisions on the way to the recommendation shown (*7 decisions · 5 by the guideline rules · 2 by AI (lowest 86%) · 0 by you*; the AI part only when AI is on). Opened, each decision lists its question (the parent box text, footnote marks removed; a page's virtual `PAGE:START` reads *Which starting point applies?*) and every option with a confidence bar (the AI's probability; a rule is full or empty) and a badge (*Rule ✓*, *Rule ✗*, *AI 92%*, *You chose*), the followed option highlighted, **Choose this instead** (sets an override), **Take back my choice** and **Show on NCCN page**. A rule/AI disagreement adds *The AI favoured 'X' (91%); the guideline rule was followed.* The walk can stop: *Your decision needed: ...* (options by confidence, one click to choose), *Not enough information to decide ...* (the missing details as buttons that open the question), or, when the AI call failed, one muted line *AI scoring unavailable — showing the guideline rules only.* With AI off the same trail shows the rules, and a step the answers do not settle appears inside it as *Still open*. The card gains *AI-assisted: 2 of 7 decisions chosen by the AI (lowest 86%). Review in How we got here.* when the AI chose any step on its route.
When nothing fits, the tab says *No recommendation fits these answers* and offers a way back to the questions; before anything is entered it asks the first questions.

### Steps on the diagram
- **Hover a step** (or focus it): a preview of the NCCN page it came from, with the step outlined. Footnote chips, principles pages and recommendation cards preview the same way. Without the PDF the preview shows the page rebuilt from the extracted layout and says how to connect the PDF.
- **Click a step**: it is highlighted together with every path through it (other paths are hidden until *Show whole diagram* or, in Advanced tools, *Other paths*), the Step tab opens, and the NCCN page opens in its own browser window, the step outlined. The same window is reused for the next step; when the browser blocks pop-ups, a floating viewer in the page is used instead (drag, resize, zoom, page through, pop out where Document Picture-in-Picture is available).
- The PDFs are found automatically when the page is served from the repository (`Guideline/`), next to a hosted copy (`pdfs/<slug>.pdf`), or from a file the user connects (kept in this browser). See `built/README.md`.

### What Advanced tools adds
Switch it on in Settings. Everything below is hidden otherwise.
- **Title bar**: *Other paths* (show the paths that do not pass the selected steps) and *Arrow certainty* (mark arrows found by only one of the two extraction methods); the *Source PDFs* menu (connect a PDF, connect a folder, forget).
- **Contents panel**: the *History* view (pages visited, guided walk); search can include results on other paths.
- **Recommendation tab**: *Start from* (choose the algorithm page the recommendations begin at), the routes view instead of the single card (*N routes fit*, *Most useful next*, ranked list with likelihood bar, criteria met and judgment calls), the selected route's scores (fit, patient data, extraction) with *How these are worked out*, every step on the route with its status (*Criteria met*, *Other arms ruled out*, *Needs details*, *Condition not encoded*), and the route summary with a FIT line.
- **Patient tab**: the box text and share of the fit on each *Decides* line, how many recommendations remain open under each choice, *Stated in the record* (enter a classification the record states, for example "low-risk") and an *override* link beside worked-out values, and a page selector under *Where is the patient now?*.
- **Step tab** always visible, with the *Branch condition* (machine-drafted, not clinician-reviewed) and *Start guided walk here*; **Walk** tab: step through the algorithm, undo, reset, copy the path.
- **Home**: encoding statistics on guideline cards and tooltips (algorithm pages, boxes, decision boxes with an encoded condition) and the map's outer arc and reference curves.
- **Help**: *About the data* (how conditions were drafted and what likelihood and confidence mean).

## AI decision support
Optional; works only through `python -m nccn_nav.serve` with `OPENAI_API_KEY` set (`built/README.md`). On start the page asks `GET /api/decide/status` (`lib/decide.ts: aiStatus`); on `file://`, on a hosted copy or without a key nothing about AI is shown. The preference (`oc-ai-on`, `oc-ai-threshold`) is kept in this browser (`lib/prefs.ts`); the default is on, threshold 0.85, range 0.5 to 0.99.
- **The walk** (`lib/aiWalk.ts`): from the start of the recommended route, each branch is decided by the clinician's override, else the encoded rules (also an option the patient already received), else the model's probabilities through `POST /api/decide` (questions `n:<node>` for condition branches, `o:<child>` for options). The top child is followed at or above the threshold; below it the walk stops and asks; a "none" above 0.5 stops with the details that are missing. `lib/useAiTrail.ts` runs the rules-only walk at once and the AI walk about 400 ms after the last answer (stale runs cancelled, answers cached in memory by facts hash); a change of choice, threshold or start runs at once.
- **Ranking.** The model's probabilities along the trail replace the even split among undecided branches in `rankPathways` (`edgeProb`), so *Other possible recommendations* are ordered by them; the clinician's choices (`overrides`) force the route through the chosen child.
- **Choices** (`overrides`: box id to child id) live in the store with the patient and are written with it (`sessionStorage`, `oc-patient:<slug>`, key `overrides`). *Start over*, *Load an example* and loading a saved patient clear them. A choice is dropped when a finished walk (not one that stopped for a decision, ended in an error or is still running) no longer passes that box or no longer offers that child (`trailView.staleOverrides`).
- **Diagram.** With AI on, the arrows of the recommended route that leave a decision carry the AI percentage, *Rule* or *You*; below the threshold they are dashed (`Canvas.tsx`, `trailView.edgeTags`).
- **Tests.** `web/test/trailUi.test.ts` (summary, stale choices, labels, hook first render) and `web/test/aiWalk.test.ts`; `node e2e/ai.mjs` serves the built page with a mocked server (status and `/api/decide` with deterministic probabilities) and checks Settings, the trail and its badges, *Choose this instead*, *Your decision needed*, *Not enough information*, the failure line, three other guidelines and the AI-off page.

## Atlas (home page)
The library opens on a map of every guideline (`web/src/atlas/`). Built from `build_atlas()` in `dashboard.py` (about 190 KB, embedded in `built/oncocarta.html` as `window.__ATLAS__`); the grouping into sites is front-end owned, in `src/nccn_nav/atlas_sites.json` (sites in ring order, plus search aliases such as CLL, GIST, RCC).
- **Site names.** Every one of the 15 sites is named at every screen size: along its arc when the name fits, else as a callout inside the ring with a leader to its arc, or a bracket beside its guidelines' names on the left and right. When the names cannot all sit cleanly beside the guideline names (smaller laptops, tablets), the home view puts sites first: a larger ring with site names, and guideline names on hover, when pointing at a site, or once zoomed in. Phones use short names (GI, GU, Gyn) where needed.
- **The map.** A search hub at the centre; 15 site sectors around it; the 91 guidelines on the outer ring, sized by algorithm pages, shaped by category (disc treatment, ring supportive care, diamond detection/prevention/risk, rounded square specific populations), with an outer arc for the share of decision boxes that have an encoded condition. The 175 references between guidelines are drawn as bundled curves through the middle (hierarchical edge bundling); pointing at a guideline lights its references with particles running from the citing to the cited guideline.
- **Original pages.** Page cards always draw the diagram; with the source PDF here, "NCCN page" in the panel swaps the card for the PDF page ("Diagram" swaps back). Hovering a box previews its whole PDF page with the box highlighted; clicking opens that page in its own browser window (one window, reused for each page opened; the floating viewer when pop-ups are blocked).
- **Levels.** Site → guideline → page → reader. A guideline opens in a "lens": its algorithm pages as a radial tree grown from its start pages (later links as dashed chords), section arcs on the rim, and its citations of other guidelines as pills on the side where those guidelines lie on the map. A page unfolds into a card with its boxes where they are printed on the PDF page, edges drawn on left to right, and chips for links to other pages; clicking a box opens its original PDF page (see above); "Read this page" opens the reader.
- **Search** at the hub ("Which cancer or topic?", docked at the top once you go in): guidelines (title, abbreviations, aliases), sites, sections and pages (titles and codes, e.g. `PROS-3`). The highlighted result lights up on the map before you choose it.
- **Patients.** In a guideline, example patients (and the patient entered in the reader this session) show their best-matching recommendation (the highest-ranked route): drawn page to page in the lens, travelled by particles, and highlighted box by box on the page cards; "Open in the reader with this patient" carries the patient over (`sessionStorage`, key `oc-patient:<slug>`).
- **Opening a guideline** is one camera flight: the camera frames the guideline with its panel already accounted for, the lens grows as the camera arrives, the guideline is read while the pointer rests on it (or after the flight), and its pages are handed over once the camera has stopped. A test checks the frame budget during the transition.
- **First steps.** A one-time hint says how to move around (click, scroll or pinch, Esc, /). A guideline's panel offers "Find a recommendation for a patient", which opens the reader on the Patient tab, and "Read the guideline".
- **Getting around.** The hash records the place (`#atlas`, `#atlas/@gi`, `#atlas/prostate`, `#atlas/prostate/PROS-3`), so Back climbs a level; Esc, clicking empty space or zooming far out does the same. The reader's "All guidelines" button returns to the atlas at the page being read. `/` focuses search; `+`, `−`, `0` zoom and refit. A keyboard tree (Tab to the map) walks sites, guidelines and pages with the arrow keys and lights each on the map. The List view (`#list`) keeps the plain list.
- **Motion.** A one-time intro per session draws the rings, sends each guideline out along its spoke and draws the references; the camera flies between levels (d3 `interpolateZoom`); lenses and cards grow with springs. Drawing happens only while something moves. With reduced motion the map is drawn at once and the camera jumps.
- **Small screens.** Search docked at the top, details as a bottom sheet, labels shown where they fit; pinch and drag to move.

## Library and reader (technical)
- **List view:** every guideline in `data/index.json`, grouped by category, with search, version and date; Advanced tools adds how much of each is encoded (algorithm pages, boxes with an encoded condition). Recently opened guidelines come first.
- **Loading:** a guideline is read when opened, from its compressed script in `built/guidelines/` (this works for a page opened from disk, where browsers refuse `fetch`), else from `data/` when served; the URL hash names it (`#prostate/flow/PROS-3`), so links, Back/Forward and bookmarks work. Example patients load from `<slug>/vignettes/examples.json` when present.
- **Between guidelines:** links typed `external_guideline` in the data, and page codes of another guideline's prefix (`DIS-A`, `LCS-11`), open that guideline at that page. The Step tab lists the other guidelines a step cites.
- **Multi-disease guidelines** (29 of 91, `sections` in the data): the patient form asks for the disease or subtype first; entry boxes carry the section condition.
- **Starting points:** in auto mode, routes start from the algorithm pages that have entry boxes and that no other page leads to (one per disease), plus entry boxes elsewhere that the entries select (own condition, else the linking boxes' `link_condition`).
- **From the data, not heuristics:** options' `received_predicate` ("already received") marks the route taken; `decision_type: condition` without a condition, and `predicate_status: rejected`, are flagged "not encoded"; structured tables pass through row by row; footnotes carry the page that defines each letter; page sizes and content bands drive the layout and previews; the connected PDF is checked against `pdf_sha256`. The older heuristics remain only for bundles without these fields (the synthetic sample).
- **Patient tab** (`web/src/components/PatientPanel.tsx`, helpers in `web/src/lib/formAssist.ts` and `extract.ts`; behaviour as the clinician sees it is under *Using OncoCarta*):
  - *Where is the patient now?* (`web/src/lib/moments.ts`): Not sure, New diagnosis, Follow-up, Recurrence or relapse, Advanced or metastatic, Later-line therapy, whichever the guideline has. Moments come from the algorithm: start pages that no other page leads to are a new diagnosis (or the first entry page when every one is linked back), and entry pages whose titles say surveillance, recurrence/relapse/progression, metastatic/castration-resistant or subsequent therapy are the later moments; a phase with several pages offers a page list (Advanced tools), and multi-disease guidelines show the chosen disease's pages. Picking one starts the routes there (the same setting as *Start from* in Advanced tools) and narrows the form to the details the branches reachable from that page use, with *Show all details* to widen it. Past a diagnosis the form is grouped by time: *Current situation* (marked "now"), *Treatment so far*, and *Original diagnosis* folded away. Moving on from a diagnosis to a later moment holds the details that described the patient then (current-state details that are not stable findings such as germline or tumour biomarkers and histology) under *Carried over from diagnosis*: they stay in the record but steer neither the routes nor the worked-out values until marked *Still true*, changed or cleared; details recorded at diagnosis and treatment history carry over as they are. Going back to a new diagnosis releases them. Hidden for screening, prevention and supportive-care guidelines.
  - *Questions that change the recommendation* first (`decidingFacts` in `formAssist.ts`): the details still unknown that decide a branch on the open routes, most consequential first (before any entry: the details the first branches turn on). Each names the page it decides (title first, code after; Advanced tools adds the box text and how much of the fit it is open on). Under each choice, where it leads: the routes are re-ranked as if that answer were given (a few at a time in the background, cached) and the page it reaches is named, when the answers lead to different places; clicking a preview chooses that answer. Everything else is under *More questions*, with details that change none of the open routes dimmed.
  - *One question at a time* is the first-visit mode (`oc-form-mode` in browser storage remembers the choice): the next deciding detail with its choices and where each leads, number keys, *Don't know — skip* and *Back*. A jump to a field from the recommendation ("add PSA") switches to the form for that visit.
  - *Paste a note*: a clinic note or report is read with plain rules from the guideline's own schema (numbers after a detail's name, staging codes like cT2b/N0/M1b, choices named in words, yes/no details by their distinguishing words with negation, age, ECOG, Gleason → Grade Group, stated risk groups), skipping times ("PSA 8 weeks after surgery"), other measures ("PSA nadir") and earlier values. Each finding shows the words it came from and what it replaces; untick any before applying. On the four hand-encoded prostate vignettes it reads 23 of their values with none wrong (`web/test/formAssist.test.ts`).
  - *Entered so far* strip (click to go to the detail, × to clear), *worked-out values* near the top (override link and *Stated in the record* in Advanced tools), *saved patients* (named, kept in this browser, `oc-saved:<slug>`, 30 at most), *checks* for implausible numbers (units, ranges) and contradictions (M0 with metastases recorded, a stated classification the entries work out differently), and *number keys* to pick a choice.
- **Labels:** labels are Title Case from the variable names, with abbreviations in capitals (ECOG, PSA, FLT3, hCG, COVID-19): a built-in list plus the words each guideline's own text writes in capitals; unit words already shown beside the input are dropped (`psa_ng_ml` → "PSA"); `lt/le/gt/ge` become < ≤ > ≥ (`web/src/lib/factMeta.ts`). Fields carry their `time` (at diagnosis, history) and judgment flag; long forms (up to 142 fields) have a filter, and fields that match no clinical group are grouped by time.

## Reader features (technical)
How the screens in *Using OncoCarta* are produced. Logic keeps the encoding names (route, arm, criteria, extraction); `web/src/lib/terms.ts` translates them for display.
- **Readable cards.** Each box's flat PDF text is parsed into a lead-in, bulleted and nested lists, tier headings (Preferred / Other Recommended / Useful in Certain Circumstances), "or" dividers between alternative regimens, and category tags (`web/src/lib/parseBox.ts`).
- **Linked everywhere.** Page references such as `PROS-A`, `PROS-F 2 of 5`, `ST-1`, `MS-12` and "See Discussion" become links in cards, footnotes, principles pages and the discussion. A principles page lists every box and footnote that cites it.
- **Highlighting a step.** Clicking a card lights up every route through it (across linked pages); other paths hide until cleared (or until *Other paths* is on, in Advanced tools).
- **Footnotes, Evidence, Preference dock** (`Dock.tsx`); footnotes step through "i of N" places.
- **Search** in a side panel: exact phrases in quotes, filter chips that gray out cards that do not apply, counts by type.
- **Patient answers.** A form built from `fact_schema.json`, with plain labels and units (`web/src/lib/factMeta.ts`), one-tap choices, numbers that accept bounds and ranges (`>10`, `5-10`), an age field with a life-expectancy helper that applies the PROS-A health-quartile adjustment, "stated classifications" (Advanced tools; for example a record that only says "low-risk"), the values worked out from the entries, and example patients from `vignettes/examples.json`.
- **Welcome screen.** First visit offers three ways in (enter a patient, try an example, read the guideline); the help text stays behind the "?" button.
- **Recommendation card** (`RecoCard` in `PathwaysPanel.tsx`). For the top-ranked route: the box after the route's last decision that carries recommendation tags (Preferred, category), else the last box that is not just a page reference (`routeFocus`), rendered with its tiers and tags; then what follows ("Then: … Open PROS-8"); the NCCN page it sits on; *Why* from the conditions the entries satisfied (`whyAnswers`); *Still unknown* from the route's open criteria. Routes that end in the same box are shown once. Advanced tools shows the full route view instead: the same recommendation, the options offered at the route's last treatment branch with the one this route takes, and the step trail with workup and pass-through steps collapsed to one line.
- **Summary.** One page to copy as text or print: entered and worked-out details, the recommendation with its structure, how well the answers match and what is still unknown, the steps with their page and PDF page, and the caveat. Advanced tools uses the route wording and adds the scores.
- **Ranked pathways** (`web/src/lib/pathways.ts`). Every route through the graph that the entries leave open, ranked:
  - *relative likelihood*: 100% shared across open routes; at each branch, arms whose condition is met share it, undecided arms share it equally (and keep a 15% residual share once a sibling is met), contradicted arms are pruned. Not a clinical probability. The plain bands are *Best match* (50% or more), *Also possible* (20% or more) and *Less likely* (5% or more).
  - *criteria met*: encoded conditions on the route the entries satisfy vs. still open. Treatment options without a condition are not counted. *Matches your answers* means none is open; otherwise *Needs N more answers*.
  - *patient data* (Complete / Partial / Sparse) and *extraction* (High / Good / Mixed) are shown separately in Advanced tools rather than as one confidence number: coverage of the route's criteria, and the mean reliability of its steps (arrow found by both extractors 1.0, image-verified 0.95, one extractor 0.7; condition not confirmed in review 0.85).
  - *not encoded*: a branch box with no condition is flagged (Advanced: "condition not encoded"; default: "your clinical judgment") and counted as an open criterion, never as met, when review rejected its drafted condition (`predicates_status.json`) or when its sibling arms have conditions; boxes the guideline lists as side-by-side options stay plain options.
  - "Best next question" names the missing fact that is open on the largest share of likelihood, and every open criterion links to its field.
  - Auto start: the algorithm pages with entry boxes that no other page leads to (one per disease), plus entry boxes elsewhere that the facts select directly (e.g. PSA recurrence) when the walk did not already pass a page leading there; initial-diagnosis routes give way once a later-state page applies. Routes stop after a recommendation when the next arms are later events (as in `navigator._auto_step`).
- **Source previews.** Hover a step, card, footnote or principles page to preview the original PDF page it came from with the box outlined; click to open that page (a separate browser window, or the floating viewer when pop-ups are blocked; drag, resize, zoom, page through, pop out with the Document Picture-in-Picture API where the browser supports it). The PDFs are licensed and never bundled or committed (`*.pdf` is gitignored); OncoCarta finds them in three ways:
  - **Served next to the data:** `--library` looks for local copies (`data/<slug>/`, `private/`, `pdf/`, `pdfs/`, or `--pdfs DIR`), matches each to its guideline by the `pdf_sha256` recorded at encoding (else by file name `<slug>.pdf`), and writes their paths (not the files) into the page; `--import-pdfs DIR` copies the matching PDFs to `data/<slug>/pdf/<slug>.pdf`, where the repository tracks them. The viewer also tries `pdfs/<slug>.pdf` next to the page (a hosted copy), `data/<slug>/pdf/<slug>.pdf`, `private/<slug>/pdf/<slug>.pdf` and `pdf/<slug>.pdf`.
  - **A folder, once:** Advanced tools → "Source PDFs" → "Connect a folder of NCCN PDFs" (or drop several PDFs on the page) matches every file to its guideline by checksum, else file name, and keeps them in this browser's IndexedDB.
  - **One file:** "Connect the NCCN PDF" (shown when this guideline's PDF is missing), or drop it on the page.
  A PDF that is not the file the guideline was encoded from is still used, with a warning (shown in the Source PDFs menu). Without a PDF, previews show the page rebuilt from the extracted box positions and say how to connect it. pdf.js is bundled so this works offline.
- **Guided walk** (Advanced tools). Step through the algorithm from any card; branches the entries decide are followed automatically.
- **Conditions.** `predicates.json` is authoritative: conditions rejected in review are left out (the raw drafts in `llm/pred_out_*.json` are used only when no `predicates.json` exists). In Advanced tools each condition shows whether review confirmed it, and every criterion shows the patient's value and whether it is met. Conditions were drafted and reviewed by a language model, not clinicians.
- **Phone layout.** Single column, contents drawer, bottom sheet for the Patient and Recommendation tabs ("Patient & recommendation"), readable default zoom.

## Data it reads
From the data folder: `merged_graphs.json` (or `e1_graphs.json`), `footnotes.json`, `pages.json` (principles, staging, discussion, and each page's PDF index), `fact_schema.json`, `predicates.json` with `predicates_status.json` (or the drafts in `llm/pred_out_*.json`), and `vignettes/examples.json`. The PDF's private-use glyphs and control characters are cleaned in `dashboard.py`; page titles come from the page text.
